Coolhole→Coolhost age-restricted YouTube cache, Docker image, playlist UX polish

Saves ~1.5 weeks of fork work that has been running locally / on the
Hetzner host but never landed in git. The upstream `streeeggs` PRs
(de608118, fc346bd2, c450ea1) are unrelated and stay below this; this
is the Coolhole-specific divergence on top of them.

Age-restricted YouTube via Coolhost cache (the headline):
- src/ytdlp.js — new wrapper around the yt-dlp binary. Spawns with
  bv*+ba/b → mp4 muxing, configurable timeout (default 120s), kills the
  child on timeout, returns stderr on non-zero exit.
- src/coolhost-cache.js — new module that asks Coolhost
  /api/cache/yt/{id} first, returns the cached file URL on hit, and
  falls through to ytdlp.downloadVideo + cache registration on miss.
  Holds an in-memory activeDownloads lock per videoId so concurrent
  joins of the same age-restricted video coalesce into one download.
- src/get-info.js — when meta.ytRating === "ytAgeRestricted" and
  yt-dlp.enabled is set, route the lookup through coolhostCache and
  return a Media of type "fi" (or "hl" for .m3u8 outputs) with
  meta.ytAgeRestricted=true, instead of failing the lookup.
- src/channel/playlist.js _addItem — now allows ytAgeRestricted media
  through when meta.ytAgeRestricted is set (i.e. it has a Coolhost
  cache backing). Bare age-restricted with no cache still fails fast
  with a clearer message ("yt-dlp not available").
- src/channel/library.js — never permanent-cache items with
  meta.ytAgeRestricted. Coolhost-cached entries expire after ~8h, so
  putting them in the channel library would create dead links the
  next time the page loads.
- src/config.js + config.template.yaml — `yt-dlp` (enabled, exec,
  timeout) and `coolhost` (url, uploads-dir, admin-password) config
  blocks, both disabled / empty by default.

Containerization:
- Dockerfile — node:18-slim base, installs ffmpeg + python3 + g++
  (needed by node-gyp for bcrypt), strips CRLF from postinstall.sh
  before running it, transpiles src/ → lib/ via babel and runs
  bin/build-player.js. EXPOSE 8080 1337.
- .dockerignore — excludes node_modules, lib/, www/cache, *.log,
  config.yaml, conf/, tor lists, *.crt/*.key, .git, etc.

Custom titles + rename feature:
- src/channel/playlist.js handleQueue — accept any non-empty trimmed
  title, not just the historical "cu"/"fi" carve-out. Length and
  sanitization are still enforced in Media.setTitle.
- src/channel/playlist.js handleRenameMedia + www/js/callbacks.js
  renameMedia — new ws message. Owners (queueby === self) and anyone
  with the settemp permission can rename a queued item; broadcasts
  the new title and updates the "Currently Playing" header if the
  renamed item is current.
- www/js/util.js makeQueueEntry / addQueueButtons — track queueby per
  item and render a pencil "Rename" button in the per-item menu when
  the viewer has permission. Uses window.prompt for now (good enough
  for this stack).
- www/js/ui.js — title input box now shows for any link that needs
  one (linkNeedsTitle: fi/cu/cm + bare coolhost.ca/f/ links), not
  only "fi". Helper text reworded ("optional — leave blank to use the
  link") and a placeholder added.

Empty-playlist fix:
- src/channel/playlist.js handleClear / _delete — when the queue
  drains, clear the lead interval, broadcast setCurrent:"" and a new
  clearMedia event so clients tear down the player instead of
  freezing on the last frame.
- www/js/callbacks.js clearMedia — destroys window.PLAYER, runs
  removeOld(), and clears the "Currently Playing" header.

Smaller polish:
- templates/channel.pug — queue-button copy ("Queue Next" / "Add to
  End"), and "Add as temporary" defaults to checked everywhere
  (matches actual usage; nothing should be permanently library-cached
  by default).
- www/js/coolhole-util.js applyHideMotd — sync the +/- glyphicon at
  load time so a page refresh while the MOTD was hidden doesn't show
  the wrong toggle icon.

Docs:
- docs/age-restricted-videos-plan.md — the plan that drove the
  cache/yt-dlp work above.
- docs/hat-customizer-plan.md (+ .pdf) — design doc for an upcoming
  hat customizer feature; not implemented in this commit.
- docs/SESSION_LOG_2026_04_07.md, _09, _12, _18 — session logs from
  the multi-day landing.

No behavior changes when yt-dlp.enabled is false (default), so this is
safe to merge ahead of installing yt-dlp / pointing at a Coolhost
instance on the host.
